# Shared scheduling and silent open-window encounters

The active BedroomPrototype_PlayerFigure scene is edited in place. No new scene, camera, player or director is created.

Diagnosis before changes: the old director used UnityEngine.Random.value correctly, but selected only among requests made after independent initial timers. Under-bed requested at15/12/10s, door25/23/21s and window30/28/26s on Nights1/2/3. Under-bed was therefore the sole initial candidate. No seed reset, list-priority rule or intentional tutorial was found. Existing random cooldowns and weighted sampling could not correct that fixed opening eligibility.

BedroomEncounterDirector now owns the initial opportunity and subsequent randomized opportunities. NightSchedule1/2/3 assets use shared initial delays18/16/14s; intervals8–14/6–11.5/4–9s; equal base weights1/1/1. All enabled, dormant, ready encounters join the same candidate pool from the first decision. No normal actor waits for its obsolete per-enemy initial delay. Door/window legacy serialized delay values are hidden for compatibility; the under-bed delay is used only with standalone/external coordinators.

Eligibility excludes disabled actors/configs, zero selection weights, non-dormant actors, actors still on individual cooldown, mandatory player transitions/closing, raised blanket, and window whenever player state is not InBed. Candidates are gathered in stable encounter-kind order, independently of hierarchy/component order. One weighted draw occurs at a scheduling opportunity, with an immediate activation recheck. Empty/blocked opportunities retry at selectionInterval; there are no per-frame chance rolls. Player operation leases and existing out-of-bed return grace are preserved. Returning to bed never restarts the night clock.

The director uses a private System.Random stream seeded once per night. Normal seeds are newly generated; useFixedSeed/fixedSeed are optional debugging controls. Night offsets make Nights2/3 distinct while reproducible. Selection, random opportunity intervals and managed random cooldowns share this stream; the global Unity random state is not reset. Restart automatic scheduling is an explicit Play-mode debug context menu, not an automatic per-frame operation.

Configure each night asset's underBedWeight, doorWeight and windowWeight. A ready open window multiplies its base weight by1.5 below15s,2 below30s,3 at/after30s, capped by WindowEncounterConfig. With base weights1/1/1 and all three eligible, the closed probabilities are1/3 each and the maximum-open probabilities are20%/20%/60%. These remain relative weights, not guaranteed attacks; cooldown and player-state exclusions redistribute probability. Closing resets open danger and enforces the existing safe cooldown.

forceFirstEncounter defaults None. Only Night1 honors a configured tutorial target, and only while it is eligible. Nights2/3 always ignore this tutorial field. No automatic rotation or forced alternation is used; legitimate random repeats remain possible.

Night1/2 currently use exclusive encounter sequences. Night3 enables overlapping warnings with maximumWarningConcurrency2. New warning starts require active actors to remain in warning stages. A shared defense reservation gates under-bed exposure, door listening and window AttackWarning so mandatory counters cannot overlap. The second warning waits without starting its reaction clock. Door/window defense stages also wait for a raised blanket to lower. The under-bed early-blanket/fresh-press rule is preserved. This architecture supports later overlap tuning without duplicating attack state machines.

Window closed: Knocking -> Opening -> HeadEmerging -> AttackWarning -> Retreat/Attack. Existing tapping escalation, latch and visible panel swing remain. Window already open: SilentApproaching -> HeadEmerging -> AttackWarning -> Retreat/Attack. The silent path does not call pane movement, knocks, latch/opening audio or monster listening/breathing audio. It also suppresses explicit attack text cues by default (showSilentAttackDebugCue is opt-in). Retreat sound after a successful counter is still allowed. Inspector defaults: silent approach1.2s, emergence2.5s, reaction2.5s, continuous face exposure0.8s. Silent emergence/reaction are not shortened by danger. Both paths use the same flashlight/range/face-ray counter and leave the panel open after retreat.

Manual silent test: enter Play mode and use Bedroom Prototype > Debug > Start Window Test Night; for isolated testing disable automaticScheduling on the existing director. F5 Force window encounter with a closed panel tests noisy mode. Repel using F and mouse aim, wait until Dormant, then Force again without closing the panel. The second attempt is silent and should be noticed visually. F5 Force window open followed by Force encounter also starts silent mode. Debug force can bypass the actor's own cooldown intentionally but still respects night/player state, active threat and transition safety. Normal automatic selections always respect cooldowns. F3/F4 and Space/R remain the existing counters.
